# zcode-pet 详细说明

README 讲安装与日常使用；这份文档讲**配置细节、计费口径、注入原理与排障**。

## 一、三个数字的口径（别混）

| 显示 | 口径 |
| --- | --- |
| `⚡本轮` | 当前这一轮对话的 token 与费用（一轮 = 一条用户消息引起的全部请求） |
| `Σ本会话` | 当前会话累计 token；**¥ 只算「当前在用的这家模型」的账** |
| `💸 本会话`(菜单) | 整个会话按厂商拆账的总账（订阅行 ¥0） |
| 成长值/等级 | **全部会话、跨工作区**累计吃掉的 token（不是当前会话），永不减少 |

费用是**逐行**按每个请求自己的 provider/model 计价的：订阅套餐（provider_id 以 `account:` 开头）一律 ¥0，失败/取消的请求 0 token 不计钱。

## 二、余额与订阅额度（三套语义）

| kind | 来源 | 显示 |
| --- | --- | --- |
| `money` | 厂商余额接口（API key） | `余¥13.57·谷(2分前)` |
| `quota` | 厂商 Coding Plan 窗口接口（API key） | `📊 用42%·5小时` |
| `plan` | **账号登录的订阅**：ZCode 自己查完写进 `~/.zcode/v2/logs/<日期>.log` 的套餐额度，脚本从日志尾部捞（512KB 分段往回翻最多 8MB + 12 小时兜底） | `📊 用17%(11分前)`，菜单带「剩 x · n 后重置」 |

- key 加密的账号订阅查不了厂商接口——但日志白送，这就是 `plan` 的来源。胶囊上的 `(n分前)` 是 ZCode 写日志的时间。
- 同一模型多份额度（如 GLM-5.3-Flash 的一次性 100M + 每日 5M）：**在「还有剩」的份额里挑用得最满的**（先耗尽的才是真约束）；某份用尽后 ZCode 会自动切下一份，胶囊跟着显示下一份；全部用尽才退回显示最满那份（⚠）。
- 自定义 API（右键「➕ 添加 API」写进 `pet-providers.json`）字段：`label/match` 必填，`price:{hit,miss,out}`（可写 `0.02,0.04` = 谷,峰，只有分两档计价的家才写两个）、`balanceUrl/balancePath`、`balanceUsedUrl/balanceScale`（中转站两接口取"总额-已用"）、`balanceAuth`（鉴权头模板，默认 `Bearer {key}`，写 `none` 表示不带）。

## 三、页面注入与版本守卫

`src/page.js` 是一段注入到 ZCode 主窗口的页面脚本（宠物/气泡/右键菜单/成就墙/面板全在里面）。页面靠**三个版本常量**决定要不要丢掉旧元素重建：

| 常量 | 守卫对象 | 什么时候 +1 |
| --- | --- | --- |
| `VER`(43) | `#tok-pet` 元素本体 | 改了页面可见行为/结构/动画 |
| `MENUV`(25) | 右键菜单函数注册 | 改了菜单项（闭包引用的函数也算） |
| `CLAMPV`(3) | 300ms 位置钳制循环 | 改了钳制逻辑 |

**守卫判断与赋值必须用同一个常量**——历史上写岔过两处字面量，症状是"改了跟没改一样"或菜单每拍重复注册。改模板后用 CDP 确认 `dataset.v` / `window.__tokPetMenuV` 真的变了。

页面脚本里的报错不会出现在 `m.error`，只在 `result.exceptionDetails` 里；`node --check` 查不出模板字符串里的语法错——所以注入失败会写进数据目录的 `.inj-err.txt`。

## 四、加新宠物

1. `node scripts/pet-add.js search <关键词>` → `preview <slug...>` 看长相（**清单名字与长相常不符，以预览图为准**）。
2. `install <slug>`：下载 → 校验宽 1536（8×192）、高为 208 整数倍 → 写 `pets.json` → 自动重启守护。
3. 素材行序约定（源自 Petdex）：8 列，row0 idle / 1 running-right / 2 running-left / 3 waving / 4 jumping / 5 failed / 6 waiting / 7 running / 8 review；v2 素材多 2 行（行偏移不变，`rows`=图高/208）。

自定义素材：按上面行序排一张精灵图，放进数据目录 `pet-<slug>/sprite.<ext>`，在 `pets.json` 登记即可（`slug/name/sprite(file:/// URL)/rows`）。

## 五、数据目录与迁移

| 模式 | 数据目录 |
| --- | --- |
| 插件 | `~/.zcode/cli/plugins/data/zcode-pet/`（由环境变量 `PET_CHIP_DATA` 注入） |
| 直接跑 | `~/.zcode/hooks/`（或自设 `PET_CHIP_DATA`） |

首次以插件目录运行时，自动从老位置**复制**（不删原文件）：`pet-state.json`、`pets.json`（精灵 URL 重写为新目录）、`pet-providers.json`、全部 `pet-<slug>` 素材目录。回滚 = 删掉插件数据目录或设回老 `PET_CHIP_DATA`。

## 六、排障速查

| 现象 | 查什么 |
| --- | --- |
| 宠物消失 | `netstat -ano \| findstr 9226`（守护在不在）→ 不在：`node src/daemon.js` 手动跑看报错；在：ZCode 是否带 `--remote-debugging-port=9222` 启动 |
| 页面有元素但全空 / 改动不生效 | 数据目录 `.inj-err.txt`（注入异常会写这里，含页面 JS 报错行号）；`node --check` 查不出模板字符串里的语法错 |
| 守护逻辑报错 | `.tick-err.txt`（tick 异常）、`.uncaught-err.txt` / `.rej-err.txt`（兜底） |
| 余额一直"获取中" | 当前 provider 没配余额接口（菜单会写明）；账号订阅读不到额度时菜单写"额度没读到"，查 `~/.zcode/v2/logs/<今天>.log` 里有没有 `billing/balance 请求完成` 行 |
| 饱食度/等级不涨 | 投喂是按轮增量记账（`fedCred`），工作时段会持续小幅上涨；完全不动先看守护是否活着、`.tick-err.txt` 有无报错 |
| 重启后重复投喂/点击乱触发 | 正常不会（有水位线 + 首拍基线 + 时间戳去重 + 未来值拒绝）。若自己往 `tokPet*Req` 写过测试值，**只能写 `Date.now()` 量级**，写大了要重启守护 |
| 加了 API 不生效 | `pet-providers.json` 手改后要重启守护（面板内添加即时生效）；「匹配」必须是 provider_id/model_id 的子串 |

## 七、给维护者的调参点

| 想改什么 | 位置 |
| --- | --- |
| 价格表 / 加厂商 | `src/pricing.js` 的 `BUILTIN_DEFS`（命中顺序 = 数组顺序；模型关键词在前、具体型号在前） |
| 峰谷时段 / 节假日 | `src/pricing.js` 的 `isPeakBJ` / `HOLIDAY_VALLEY`（**每年 11 月补次年日期**） |
| 投喂换算 / 饱食衰减 | `src/pet-state.js` 的 `FEED_TOK_PER_POINT`/`FEED_GAIN_MIN/MAX`；`src/daemon.js` 的 `SAT_DECAY_MS` |
| 等级阈值 / 成就 | `src/pet-state.js` 的 `LEVELS` / `TITLES` / `ACH_DEFS` |
| 台词池 | `src/daemon.js` 的 `DEV_QUOTES` / `HUNGRY_LINES`；天气表在 `src/weather.js` |
| 心跳/轮询节奏 | `src/config.js` 的 `POLL_MS` 等 |
